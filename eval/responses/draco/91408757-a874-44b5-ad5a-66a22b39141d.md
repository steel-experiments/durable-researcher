# Cloud Platform Comparison for Petabyte-Scale Genomics Analysis
### AWS HealthOmics vs. Google Cloud (Healthcare API / Terra.bio) vs. Microsoft Azure Genomics

---

## Executive Summary

AWS HealthOmics emerges as the most purpose-built and currently viable platform for petabyte-scale genomics at 100,000 genomes/year, offering managed workflow support for WDL, Nextflow, and CWL, predictable per-sample pricing, and HIPAA-eligible infrastructure. Google Cloud provides a strong ecosystem—Terra.bio on Google infrastructure plus the Healthcare API—especially for federated, open-science collaboration, but introduces complex and potentially costly egress structures at scale. **Microsoft Azure Genomics is being retired (March 31, 2025)** and should be excluded from any forward-looking procurement decision unless replaced by a new Azure offering.

---

## 1. Bioinformatics Tool Availability

### AWS HealthOmics
- **Workflow languages:** Native support for **WDL, Nextflow, and CWL**—the three dominant bioinformatics workflow languages [1].
- **Ready2Run workflows:** Pre-configured pipelines from **NVIDIA, Sentieon, Element Biosciences, Ultima**, plus open-source tools including **Broad Institute's GATK** best-practices workflows and **AlphaFold** for protein structure prediction [2].
- **Private workflows:** Custom bioinformatics scripts can be deployed with full flexibility, billed per-second with a 60-second minimum [2].
- **Scale:** Designed to scale across **100,000+ concurrent vCPUs** with zero infrastructure management, supporting tens of thousands of tests per day [1].

### Google Cloud (Healthcare API + Terra.bio)
- **Healthcare API:** Primarily a data ingestion and storage layer for FHIR (R4, STU3, DSTU2), HL7v2, and DICOM formats—not a workflow execution engine. Integrates with **BigQuery, AutoML, Gemini, and Vertex AI** for downstream analytics [5].
- **Terra.bio:** (Operates on Google Cloud infrastructure.) Terra is the Broad Institute's platform supporting **WDL workflows via Cromwell**, with access to GATK, thousands of curated bioinformatics tools, and extensive genomic datasets (e.g., UK Biobank, All of Us). Note: Terra's documentation pages were largely inaccessible during research, indicating a portal-gated experience [3].
- **Gap:** Unlike AWS HealthOmics, Terra.bio is not a first-party Google product. Procurement involves a third-party relationship (Broad Institute / Verily), adding contractual complexity.

### Microsoft Azure Genomics
- **Tooling:** Limited to a cloud implementation of **BWA-MEM + GATK** (the Broad Institute's best-practices secondary analysis pipeline) [4].
- **Workflow languages:** No support for WDL, Nextflow, or CWL. The service accepts only FASTQ and BAM inputs via its proprietary API [4].
- **⚠️ CRITICAL: Service retirement announced for March 31, 2025** [6]. Microsoft has not announced a direct replacement. This effectively removes Azure from consideration as a primary platform.

**Winner: AWS HealthOmics** — Broadest native workflow language support, deepest Ready2Run catalog, and no third-party dependency for core bioinformatics capabilities.

## 2. Multi-Jurisdictional Compliance (HIPAA / GDPR / China PIPL)

| Framework | AWS HealthOmics | Google Cloud | Azure Genomics |
|---|---|---|---|
| **HIPAA** | HIPAA-eligible service [1] | BAA available; Healthcare API designed for PHI [5] | HIPAA-compliant, ISO 27001/27018/9001 [4] |
| **GDPR** | EU regions available; GDPR DPA offered | EU regions; GDPR compliance program | EU regions; GDPR compliance program |
| **China PIPL / CSL** | AWS China (Ningxia/Beijing) operated by Ningxia Western Cloud Data / Beijing Sinnet — legally separate entity [7] | Google Cloud has **no China mainland regions** | Azure China (21Vianet) operates independently |

**Key compliance reality for simultaneous multi-jurisdictional operation:**

No single cloud platform can simultaneously satisfy HIPAA, GDPR, and China's PIPL/CSL/DSL within a unified control plane. All three providers require:

1. **Data residency enforcement:** Chinese genomic/health data must remain on China-mainland infrastructure under PIPL, which prohibits cross-border transfer without CAC approval. AWS and Azure each operate legally separate China entities (Sinnet/NWD and 21Vianet respectively), meaning China data cannot be federated with US/EU data on the same account.
2. **GDPR requirements:** EU resident genomic data must stay in EU regions (or rely on adequacy decisions/Schrems II-compliant SCCs for US transfers).
3. **Architecture implication:** A compliant architecture requires **three separate cloud deployments** (US, EU, China) with no cross-border data flow—only metadata/aggregate results shared.

**AWS has a marginal advantage** because it operates China regions via independent entities and can serve as the single provider across all three geographies (albeit on separate accounts). Google Cloud **cannot operate in mainland China**, eliminating it for China-resident genomic data. Azure similarly operates China regions via 21Vianet.

## 3. Federated Analysis Across Institutions

### AWS HealthOmics
- No native federated analysis framework. Federation would require custom architecture using **AWS HealthOmics + S3 cross-account access + IAM federation**.
- The Variant Store provides zero-ETL integration with Athena and SageMaker, enabling cohort queries across datasets within a single AWS account or via AWS Organizations [2].
- Cross-institution federation would need to be built on top of AWS networking (VPC peering, PrivateLink, Transit Gateway) with custom data-sharing agreements.

### Google Cloud / Terra.bio
- **Terra is the strongest federated analysis platform.** It powers major collaborative genomics consortia including the NHGRI's AnVIL (Genomic Data Science Analysis, Visualization, and Informatics Lab-space) and supports the **GA4GH Data Repository Service (DRS)** standard for referencing datasets across institutions.
- Terra's workspace model allows multiple institutions to share workflows and reference each other's data without centralizing it, which is the essence of federated analysis.
- Google Cloud's **BigQuery** and **Dataproc** can be used for cross-institutional analytics, though genomic data federation at petabyte scale requires careful architecture.
- **Beacon Network** and GA4GH standards (developed with heavy Google/Broad participation) are natively supported in the Terra ecosystem.

### Azure
- No native federated genomics framework. With Azure Genomics retiring, this gap is now unresolvable on the current service.

**Winner: Google Cloud / Terra.bio** — Purpose-built for multi-institutional collaborative genomics with GA4GH standards support. If federated analysis is a top requirement, this is a decisive advantage.

## 4. Performance for Variant Calling Pipelines

### AWS HealthOmics
- Scales to **100,000+ concurrent vCPUs** for workflow runs [1].
- Ready2Run variant calling workflows from **Sentieon** and **NVIDIA** (Parabricks) offer GPU-accelerated pipelines that can reduce GATK best-practices runtime from ~30 hours to under 2 hours per whole genome [2].
- **EBS-optimized instances** deliver up to 4,000 Mbps dedicated throughput, critical for I/O-heavy variant calling [7].
- No published public benchmarks comparing HealthOmics-specific performance.

### Google Cloud / Terra.bio
- Terra runs workflows on **Google Cloud Life Sciences** (formerly Pipelines API), which provisions GCE VMs including GPU-enabled instances.
- **NVIDIA Clara Parabricks** is available on Google Cloud and can achieve similar GPU-accelerated variant calling.
- Google's **Batch** service supports high-throughput genomics workloads with spot VM pricing.
- No directly comparable public benchmarks between HealthOmics and Google Cloud for variant calling at 100K-genome scale.

### Azure
- BWA-GATK pipeline with 99.99% availability SLA [4]. No GPU-accelerated option documented. Service is retiring.

**Assessment:** AWS and Google Cloud are roughly equivalent in raw compute capability for variant calling. The deciding factor is **Sentieon/NVIDIA Ready2Run workflows on HealthOmics** (lower operational overhead) vs. **Terra's pre-built GATK workflows** (more community support, open-science heritage). Neither provider publishes head-to-head benchmark data at 100K scale.

## 5. Total Cost of Ownership: 100,000 Whole Genomes/Year

### Assumptions
- Average whole genome: ~130 GB raw data (FASTQ) per genome [2]
- Annual raw data ingest: ~13 PB
- Variant calling output: ~1 GB per genome (VCF/gVCF)
- 5-year retention of raw data with tiered storage

### AWS HealthOmics Cost Estimate

| Cost Component | Unit Cost | Annual (100K genomes) |
|---|---|---|
| **Sequence Store (Active)** | $0.005769/GB-month [2] | ~$9.0M/year (130 GB × 100K × 12 months) |
| **Sequence Store (Archive, after 30 days)** | $0.001154/GB-month [2] | ~$1.8M/year if tiered aggressively |
| **Variant Store** | $0.035/GB-month [2] | ~$42K/year (1 GB × 100K × 12) |
| **Compute (variant calling, est. Sentieon)** | ~$3–7 per genome (Ready2Run) | ~$300K–$700K |
| **Data staging (imports/exports)** | Complimentary compute [2] | $0 |
| **AWS estimate for storage alone** | $10.78/genome over 5 years [2] | ~$1.08M/year storage |

**Rough AWS annual TCO: $2–4M** (storage-heavy, compute varies by pipeline choice)

### Google Cloud Cost Estimate

| Cost Component | Unit Cost | Annual (100K genomes) |
|---|---|---|
| **Cloud Storage (Standard, ~130 GB/genome)** | ~$0.020/GB-month | ~$3.1M/year |
| **Cloud Storage (Nearline/Cold, tiered)** | ~$0.006–0.010/GB-month | ~$1.0–$1.6M/year |

**Rough Google annual TCO: $2–5M** (highly dependent on storage tier and Terra pricing)

### Azure Genomics
- Microsoft offered per-genome pricing but the service is **retiring March 31, 2025** [6]. Not viable for TCO modeling.

**Cost assessment:** AWS and Google are in the same ballpark, but AWS HealthOmics has **more predictable pricing** (pay-per-sample Ready2Run, complimentary data staging) whereas Google Cloud costs escalate with Healthcare API operations and Terra licensing.

## 6. Data Egress Cost Traps ⚠️

This is the single most dangerous area for petabyte-scale genomics and deserves detailed attention.

### AWS Egress Traps
- **Internet egress:** After the first 100 GB/month free tier, standard egress pricing applies. At petabyte scale, moving 1 PB out of AWS costs roughly **$70,000–$90,000** [7].
- **HealthOmics-specific:** AWS bills for data streamed even if the receiving application aborts the download prematurely [2]. This is a hidden cost for unreliable connections during large dataset transfers.
- **Cross-AZ transfer:** HealthOmics waives cross-AZ charges for data staging, but standard AWS services do not ($0.01/GB in each direction) [2].
- **China/GovCloud exclusion:** Free tier egress excludes China and GovCloud regions, which will have higher rates [7].
- **500 TB/month threshold:** If data transfer exceeds 500 TB/month, customers must contact AWS sales—no self-service pricing above this tier [7].

### Google Cloud Egress Traps
- **Premium Tier (default) egress:** $0.12/GiB for first 10 TiB, dropping to $0.085/GiB above 10 TiB for NA/EU/Asia [8].
- **China destination surcharge:** **$0.23/GiB** (highest tier), dropping to $0.20/GiB above 10 TiB [8]. This is nearly **3× the cost** of North American egress.
- **Healthcare API export charges:** Batch exports cost **$0.09–0.19/GB**; streaming exports cost **$0.24–0.34/GB** [5]. These are *in addition to* standard GCP network egress fees.
- **Using external IPs for VM-to-VM communication** triggers internet egress rates even within the same region—use internal IPs only [8].
- **Inter-region VM transfer:** $0.02–0.14/GiB depending on region pair (Asia is most expensive) [8].

### Azure Egress Traps
- Standard Azure egress: ~$0.087/GB for first 10 TB (North America), with volume discounts. China regions operated by 21Vianet have separate pricing.
- With Azure Genomics retiring, the next-generation replacement would determine the full cost structure.

### Quantified Egress Impact

| Scenario | AWS | Google Cloud |
|---|---|---|
| **1 PB internet egress (US)** | ~$70K–90K | ~$100K–120K |
| **1 PB egress to China** | Contact sales (high) | ~$220K–230K |
| **Federated analysis, 10 PB inter-region transfer/year** | ~$100K–200K | ~$100K–250K |
| **Healthcare API exports (10 PB/year)** | N/A | ~$900K–$1.9M (API fees alone) |

**Critical recommendation:** Budget **15–25% of total project cost** for data egress, and architect workflows to minimize cross-cloud and cross-region data movement. Process data where it resides.

## 8. Recommendation

### Primary Platform: AWS HealthOmics
Best fit for a biotech company processing 100,000 whole genomes/year due to the broadest tool availability, predictable per-sample pricing, complimentary data staging, and China region presence. Estimated annual TCO: **$2–4M**.

### For Federated Analysis: Hybrid with Google Cloud / Terra.bio
If multi-institutional collaboration is a core requirement (e.g., clinical trial networks, academic partnerships), deploy a **hybrid architecture**: primary pipeline on AWS HealthOmics, with Terra.bio as the collaboration/federation layer. Budget for egress between the two platforms.

### Azure: Exclude from Evaluation
Azure Genomics retires March 31, 2025, with no announced replacement. Microsoft's broader healthcare/AI portfolio (Azure Health Data Services, Fabric) may evolve, but is not currently suitable for petabyte-scale genomics workflows.

### Data Egress Mitigation Strategy
1. **Process data in-region** — never move raw FASTQ files between clouds or regions.
2. **Share only variant calls/aggregate results** (~1 GB/genome vs. 130 GB raw) for federated analysis.
3. **Negotiate Committed Use Discounts / Private Pricing Agreements** with egress allowances at petabyte scale.
4. **Use cloud-specific transfer services** (AWS Direct Connect, Google Cloud Interconnect) for sustained institutional links — these have lower per-GB rates than internet egress.
5. **China data compliance is architecturally impossible to federate** — plan a standalone China-region deployment with no cross-border genomic data flow.

## Uncertainty & Gaps

- **Terra.bio details** were largely inaccessible (portal-gated). Specific tool catalogs, pricing tiers, and current federated capabilities require direct engagement with the Broad Institute.
- **No head-to-head benchmark data** exists (or is publicly available) comparing variant calling throughput across HealthOmics vs. Google Cloud at 100K-genome scale. Performance claims rely on individual provider statements.
- **China PIPL compliance for genomic data** is an evolving regulatory landscape. The classification of whole-genome sequencing data under China's Data Security Law (DSL) as "important data" vs. "core data" has enforcement implications that remain ambiguous.
- **Azure's genomics roadmap** post-retirement is unknown. Microsoft may announce a replacement service built on Azure Health Data Services or Fabric.
- **Google Cloud's lack of China mainland regions** is confirmed based on current infrastructure, but joint-venture arrangements (similar to AWS/Azure) could change.
- **Sentieon and NVIDIA Parabricks per-genome costs** are estimated from general industry knowledge; actual Ready2Run pricing on HealthOmics may differ.
