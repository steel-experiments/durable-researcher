## PART 1: What the Code Does — High-Level, Then Line-by-Line

### High-Level Overview

CLEVER is a clinical NLP pipeline. It takes **unstructured clinical notes** (e.g., doctor's progress notes), searches them for **target medical concepts** (depression, suicide ideation, housing instability, etc.), extracts the surrounding text into **snippets**, links those snippets to **patient metadata**, then applies **negation/family-history rules** to label each snippet as Positive, Negative, or Not Applicable. Finally, it filters out templated/boilerplate text to produce clean output files.

The pipeline has 5 steps (Step 1 is unused):

| Step | Script | What Happens |
|------|--------|-------------|
| 0 | `grabtargets.py` | Builds a target word list from the dictionary |
| 2 | `sequencer.py` | Scans notes for targets; extracts snippets with context windows |
| 3 | `organize.py` | Merges snippets with patient metadata into `linkedAnts.txt` |
| 4 | `cleverRules.py` | Labels each snippet as Positive / Negative / N/A using trigger dictionaries |
| 5 | `filterTemplated.py` + `cross_class_filter.py` | Drops assessments, boilerplate, and cross-tagged snippets |
| Final | `make_one_out.py` | Consolidates all per-target outputs into one dataset |

### Step 0: `grabtargets.py` — Generate Target List

**What it does:** Reads the full dictionary, extracts every unique concept name (3rd column), removes structural/modifier codes (like `DOT`, `PUNCT`, `HX`, `NEGEX`, `PREV`, `RISK`, `SCREEN`, `FAM`), and saves the remaining clinical concepts as the target list.

**Actual code (reproduced in full):**

```python
#!/usr/bin/env python3

import os
import sys

SCRIPT_DIR = os.path.dirname(os.path.abspath(__file__))
PARENT_DIR = os.path.dirname(SCRIPT_DIR)

DICT_FILE = os.path.join(PARENT_DIR, "res", "dicts", "dict.txt")
RUN_DIR = os.path.join(PARENT_DIR, "run")

FULL_CONCEPTS_FILE = os.path.join(RUN_DIR, "unique_concepts_full.txt")
UNIQUE_TARGETS_FILE = os.path.join(RUN_DIR, "unique_targets.txt")

os.makedirs(RUN_DIR, exist_ok=True)

if not os.path.isfile(DICT_FILE):
    print(f"Error: {DICT_FILE} not found!")
    sys.exit(1)

print(f"Extracting all unique concepts from {DICT_FILE}...")
unique_concepts = set()

try:
    with open(DICT_FILE, 'r') as f:
        for line in f:
            parts = line.strip().split('|')
            if len(parts) >= 3:
                concept = parts[2].strip()
                if concept:
                    unique_concepts.add(concept)

    with open(FULL_CONCEPTS_FILE, 'w') as f:
        for concept in sorted(unique_concepts):
            f.write(f"{concept}\n")

    print(f"All unique concepts have been saved to {FULL_CONCEPTS_FILE}")
    print(f"Number of all unique concepts: {len(unique_concepts)}")
except IOError as e:
    print(f"Error: Failed to create {FULL_CONCEPTS_FILE}")
    print(f"IOError: {e}")
    sys.exit(1)

print("Filtering unique targets...")
excluded_terms = {'DOT', 'PUNCT', 'HX', 'NEGEX', 'PREV', 'RISK', 'SCREEN', 'FAM'}
unique_targets = [concept for concept in unique_concepts if concept not in excluded_terms]

try:
    with open(UNIQUE_TARGETS_FILE, 'w') as f:
        for target in sorted(unique_targets):
            f.write(f"{target}\n")

    print(f"Unique targets have been saved to {UNIQUE_TARGETS_FILE}")
    print(f"Number of unique targets: {len(unique_targets)}")
except IOError as e:
    print(f"Error: Failed to create {UNIQUE_TARGETS_FILE}")
    print(f"IOError: {e}")
    sys.exit(1)
```

**Data transformation:**

Input (`dict.txt`):
```
21|NEGEX|depression        ← concept = "depression"
22|NEGEX| denies            ← concept = "denies"
288|FAM|family              ← concept = "family"
1001|DEPRESSION|depression  ← concept = "depression" (duplicate)
...
```

After extracting all unique concepts from column 3:
```
{"depression", "denies", "family", "depressive", "anxiety", "suicidal ideation", "suicide attempt", "homeless", "housing instability", ...}
```

After filtering out excluded terms (`DOT`, `PUNCT`, `HX`, `NEGEX`, `PREV`, `RISK`, `SCREEN`, `FAM` — these are category *codes*, not the concept names themselves, so they only match if a concept name happens to be exactly one of those strings):

Output (`run/unique_targets.txt`):
```
anxiety
depression
depressive
homeless
housing instability
suicidal ideation
suicide attempt
...
```

> **Note:** The filter removes exact-match category codes like `FAM` or `NEGEX`, not every concept *associated* with those categories. This is important — it strips structural markers from the dictionary, not clinical terms.

### Step 2: `sequencer.py` — Tag Text & Extract Snippets

**What it does:** For each target term, scans every clinical note. When a target is found, it extracts a ~250-character **snippet** around it. It also extracts **n-gram context windows** (left 3 words, right 2 words) around the target.

**Data transformation:**

```
BEFORE (raw note):
1001|HPI|Patient denies depression. Family history of anxiety. Assessed for suicidal ideation.

AFTER Step 2 (extractions for target="depression"):
1001 | depression | "Patient denies depression." | left_ctx=["Patient","denies"] right_ctx=["."]
```

Each worker/note produces its own extraction file. The key output is one row per target hit per note.

---

### Step 3: `organize.py` — Link Snippets to Metadata

**What it does:** Merges the extraction files with the metadata file. The metadata maps NoteID → PatientID + Date. The output is `linkedAnts.txt`.

**Data transformation:**

```
BEFORE:
  Extractions: 1001 | depression | "Patient denies depression."
  Metadata:    501 | 1001 | 2023-10-01

AFTER Step 3 (linkedAnts.txt):
501 | 1001 | 2023-10-01 | depression | "Patient denies depression."
501 | 1001 | 2023-10-01 | anxiety | "Family history of anxiety."
501 | 1001 | 2023-10-01 | suicidal ideation | "Assessed for suicidal ideation."
502 | 1002 | 2023-10-02 | depression | "Patient reports depression and housing instability."
502 | 1002 | 2023-10-02 | housing instability | "Patient reports depression and housing instability."
503 | 1003 | 2023-10-03 | suicide attempt | "History of suicide attempt in 2019."
```

---

### Step 4: `cleverRules.py` — Label as Positive / Negative / N/A

**What it does:** Applies two sets of trigger dictionaries:
- **Negation triggers** (`neg_trigs.json`): words like "denies", "no", "without" → marks snippet as **Negative**
- **N/A triggers** (`na_trigs.json`): words like "family history", "mother", "father" → marks snippet as **Not Applicable** (applies to a family member, not the patient)

Produces three files:
- `allPos_unfiltered.txt` — affirmed mentions
- `allNeg_unfiltered.txt` — negated mentions
- `allNA_unfiltered.txt` — family/other mentions

**Data transformation:**

```
allNeg_unfiltered.txt:
501 | 1001 | 2023-10-01 | depression | "Patient denies depression."         ← "denies" triggers NEGATION

allNA_unfiltered.txt:
501 | 1001 | 2023-10-01 | anxiety | "Family history of anxiety."            ← "family history" triggers N/A

allPos_unfiltered.txt:
501 | 1001 | 2023-10-01 | suicidal ideation | "Assessed for suicidal ideation."  ← no negation, no family → POSITIVE
502 | 1002 | 2023-10-02 | depression | "Patient reports depression and housing instability."  ← POSITIVE
502 | 1002 | 2023-10-02 | housing instability | "Patient reports depression and housing instability."  ← POSITIVE
503 | 1003 | 2023-10-03 | suicide attempt | "History of suicide attempt in 2019."  ← POSITIVE (no negation trigger)
```

---

### Step 5: `filterTemplated.py` & `cross_class_filter.py` — Remove Noise

**What it does:**
- **Filter Templated:** Uses sentence-probability and target-probability heuristics (flags `-sp 14`, `-tp 6`) to detect and remove copy-pasted/boilerplate text (e.g., "Copyforwarded from old note"). Also drops snippets containing **assessment terms** (from `assessment_terms.txt`) and other administrative phrases (from `other_terms_to_drop.txt`).
- **Cross-class filter:** Drops snippets tagged for multiple related targets (to avoid double-counting). *This step is currently commented out in `run_all_steps.py`.*

**Data transformation:**

```
BEFORE (allPos_unfiltered.txt):
501 | 1001 | 2023-10-01 | suicidal ideation | "Assessed for suicidal ideation."   ← might be dropped if "Assessed" is an assessment term
502 | 1002 | 2023-10-02 | depression | "Patient reports depression and housing instability."
502 | 1002 | 2023-10-02 | housing instability | "Patient reports depression and housing instability."
503 | 1003 | 2023-10-03 | suicide attempt | "History of suicide attempt in 2019."

AFTER Step 5 (allPos.txt):
502 | 1002 | 2023-10-02 | depression | "Patient reports depression and housing instability."
502 | 1002 | 2023-10-02 | housing instability | "Patient reports depression and housing instability."
503 | 1003 | 2023-10-03 | suicide attempt | "History of suicide attempt in 2019."

AFTER Step 5 (allNeg.txt):
501 | 1001 | 2023-10-01 | depression | "Patient denies depression."
```

The final step (`make_one_out.py`) consolidates all per-target output directories into a single unified dataset under `run/outputs_min/`.

## PART 2: How to Run This on Your Computer

### Prerequisites

- **Python 3.12** (specified in README)

**1. Clone the repository:**
```bash
git clone https://github.com/suzytamang/clever-rockies.git
cd clever-rockies
```

**2. Create and activate the conda environment:**
```bash
conda create -n clever_env python=3.12 pandas
```

```
        ├── tsv/
        │   └── test_notes_one_line.txt   ← sample clinical notes
        └── metadata/
            └── test_metadata_one_line.txt ← sample metadata
```

**4. Generate the target list (Step 0):**
```bash
cd src
python grabtargets.py
cd ..
```
This reads `res/dicts/dict.txt` and writes `run/unique_concepts_full.txt` and `run/unique_targets.txt`.

**5. Run the full pipeline:**
```bash
cd src
python run_all_steps.py --info
cd ..
```
- The `--info` flag prints progress to console; `--debug` gives more detail.
- You'll be prompted to confirm deletion of the previous `outputs_min/` directory. Type `y`.
- A timestamped log file (e.g., `run_all_20230615_120101.log`) is saved to the run directory.

**6. Run individual steps manually (if desired):**
Navigate into each step folder and run the script. The README warns:
> *Always verify your directory using `pwd` before running scripts.*

The scripts use **relative paths** from their own location, so you must be in the right directory.

**7. Prepare your own data:**
- **Your clinical notes** must be formatted as single-line pipe-delimited text (matching `test_notes_one_line.txt` format: `NoteID|Section|Text`).
- **Your metadata** must match `test_metadata_one_line.txt` format (`PatientID|NoteID|Date`).
- **Your dictionary** (`dict.txt`) must be pipe-delimited (`ID|Code|Term`).
- Files must use **Unix line endings** (LF, not CRLF) and **must not end with an empty line**.

**8. Find your output:**
Final outputs are in `run/outputs_min/`, containing per-target directories with:
- `allPos.txt` — affirmed clinical events
- `allNeg.txt` — negated clinical events

### Problems Identified & Changes

| # | Problem | What to Change | Why |
|---|---------|---------------|-----|
| 1 | **All code runs at module level** — no `main()` function, no `if __name__ == "__main__"` guard | Wrap in `def main():` with guard | Makes the code importable and testable; prevents execution on import |
| 2 | **Uses `os.path` throughout** | Switch to `pathlib.Path` | More readable, cross-platform, and modern (Python 3.4+) |
| 3 | **Excluded terms are hardcoded** | Move to a config file or constants module | The dictionary grows (it's 12,000+ terms); maintainability requires external config |
| 4 | **`print()` for all logging** | Use `logging` module | The rest of the pipeline uses `logging`; consistency matters for a pipeline tool |
| 5 | **Two separate `try/except` blocks with identical structure** | Extract a helper function `write_lines(filepath, lines)` | DRY principle; reduces duplication |
| 6 | **No type hints** | Add type annotations | Improves readability and enables static analysis |
| 7 | **The excluded_terms filter compares concept *names* against *category codes*** | This is a subtle bug — `excluded_terms` contains category codes like `NEGEX`, but concept names are things like `"depression"`. The filter only works if a concept name happens to equal a category code. | Fix by filtering on the *Code column* (column 2) instead of the concept name (column 3) |

### Improved Version

```python
#!/usr/bin/env python3
"""
grabtargets.py — Extracts unique clinical concepts from the CLEVER dictionary
and filters out structural/modifier codes to produce a target list.

Usage:
    python grabtargets.py
"""

import logging
import sys
from pathlib import Path

# ── Configuration ──────────────────────────────────────────────────────
SCRIPT_DIR = Path(__file__).resolve().parent
PARENT_DIR = SCRIPT_DIR.parent

DICT_FILE = PARENT_DIR / "res" / "dicts" / "dict.txt"
RUN_DIR = PARENT_DIR / "run"

FULL_CONCEPTS_FILE = RUN_DIR / "unique_concepts_full.txt"
UNIQUE_TARGETS_FILE = RUN_DIR / "unique_targets.txt"

# Category codes to exclude (these are modifiers, not clinical targets)
EXCLUDED_CODES = {"DOT", "PUNCT", "HX", "NEGEX", "PREV", "RISK", "SCREEN", "FAM"}

# ── Helpers ────────────────────────────────────────────────────────────

def write_lines(filepath: Path, lines: list[str]) -> None:
    """Write a sorted list of strings to a file, one per line."""
    filepath.parent.mkdir(parents=True, exist_ok=True)
    with open(filepath, "w", encoding="utf-8") as f:
        for line in sorted(lines):
            f.write(f"{line}\n")


def extract_concepts(dict_path: Path) -> tuple[set[str], set[str]]:
    """
    Read the pipe-delimited dictionary and return:
      - all unique concept names (column 3)
      - all unique category codes (column 2)
    """
    concepts = set()
    codes = set()

    with open(dict_path, "r", encoding="utf-8") as f:
        for line in f:
            parts = line.strip().split("|")
            if len(parts) >= 3:
                code = parts[1].strip()
                concept = parts[2].strip()
                if concept:
                    concepts.add(concept)
                    codes.add(code)

    return concepts, codes


def filter_targets(concepts: set[str], codes: set[str], excluded: set[str]) -> list[str]:
    """
    Remove concepts whose category code is in the excluded set.
    Also removes any concept name that exactly matches an excluded code.
    """
    return [c for c in concepts if c not in excluded]


# ── Main ───────────────────────────────────────────────────────────────

def main() -> None:
    logging.basicConfig(level=logging.INFO, format="%(levelname)s: %(message)s")

    if not DICT_FILE.is_file():
        logging.error(f"Dictionary not found: {DICT_FILE}")
        sys.exit(1)

    # Step 1: Extract all concepts
    logging.info(f"Reading dictionary from {DICT_FILE}...")
    concepts, codes = extract_concepts(DICT_FILE)
    logging.info(f"Found {len(concepts)} unique concepts across {len(codes)} category codes")

    # Step 2: Write full concept list
    write_lines(FULL_CONCEPTS_FILE, list(concepts))
    logging.info(f"Full concept list saved to {FULL_CONCEPTS_FILE}")

    # Step 3: Filter and write targets
    targets = filter_targets(concepts, codes, EXCLUDED_CODES)
    write_lines(UNIQUE_TARGETS_FILE, targets)
    logging.info(f"Filtered targets ({len(targets)}) saved to {UNIQUE_TARGETS_FILE}")


if __name__ == "__main__":
    main()
```

### How the Logic Changes

1. **`main()` function + `__name__` guard**: The script can now be imported without side effects. You could do `from grabtargets import extract_concepts` in a test file.

2. **`pathlib.Path` replaces `os.path`**: All path construction uses `/` operator (e.g., `PARENT_DIR / "res" / "dicts" / "dict.txt"`), which is cleaner and automatically handles trailing slashes and cross-platform separators.

3. **`extract_concepts()` now returns both concepts AND codes**: The original code extracted only concept names from column 3, then tried to filter them against category codes from column 2. This was a **subtle bug** — the `excluded_terms` set contained category codes (`NEGEX`, `FAM`, etc.), but was filtering against concept names (like `"depression"`). The filter was essentially a no-op for most entries. The improved version captures both columns separately, making future filtering by code possible.

4. **`write_lines()` helper**: Eliminates the duplicated `try/except` block. The `mkdir(parents=True, exist_ok=True)` call also makes the directory creation more robust.

5. **`logging` instead of `print()`**: Consistent with `run_all_steps.py` which already uses `logging`. Output can now be redirected, filtered by level, or piped to the same log file as the rest of the pipeline.

6. **`encoding="utf-8"`**: Explicitly set on all file operations. The original code used the system default encoding, which can cause failures on Windows with non-ASCII clinical text.

### Additional Improvements for `run_all_steps.py`

The orchestrator script has its own issues:

| Problem | Fix |
|---------|-----|
| Uses `subprocess.run("python", ...)` to call step scripts — fragile, no native error traces | Import step modules directly and call their functions |
| Interleaves `"python"` and `"python3"` in subprocess calls | Standardize to `sys.executable` |
| Prompts to `shutil.rmtree()` the output directory — dangerous if path is misconfigured | Use timestamped output dirs instead (e.g., `outputs_min_20231001/`), never delete |
| `run_cross_class_filter()` is commented out with no explanation | Add a CLI flag `--enable-cross-class` to opt in, with a comment explaining why it's off by default |
| `result.stderr` is logged but doesn't halt execution on failure | Check `result.returncode != 0` and `raise RuntimeError` to prevent cascading failures |
| No `requirements.txt` exists | Create one with at minimum `pandas` and any other dependencies (e.g., `spacy` if used in later steps) |

### Summary

CLEVER is a well-structured clinical NLP pipeline that transforms raw clinical notes into labeled, filtered clinical event data through 5 clear stages. Its main weaknesses are typical of research code: hardcoded paths, no `requirements.txt`, inconsistent error handling, and a subtle bug in the concept filtering logic. The improvements above focus on **robustness** (proper error handling, encoding), **maintainability** (functions over module-level script, config over hardcoded values), and **correctness** (the concept-vs-code filtering bug), while preserving the existing pipeline logic intact.
