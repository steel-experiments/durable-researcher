# Migration Guide: Spring Boot 2.3.2 / Hibernate 5.3.22 / Java 17 → Spring Boot 2.7.14 / Java 21 (Introducing Hibernate)

## Executive Summary

Migrating a Hibernate 5.3.22 project from Spring Boot 2.3.2 (Java 17) into a Spring Boot 2.7.14 (Java 21) repository that doesn't yet use Hibernate involves a **multi-version jump across four Spring Boot releases** and a **Hibernate minor-version upgrade from 5.3 to 5.6**. The biggest risks are: accumulated breaking changes across Spring Boot 2.4–2.7, Java 21 running on an officially unsupported Spring Boot generation, Hibernate naming strategy shifts, and the introduction of Hibernate into a greenfield dependency tree. With disciplined dependency management and regression testing, this migration is feasible—but it requires careful attention to the details below.

---

## 1. Hibernate Version Alignment: 5.3.22 → 5.6.15.Final

**Spring Boot 2.7.14 manages and defaults to Hibernate 5.6.15.Final** [1][2]. Do **not** attempt to bring Hibernate 5.3.22 into the new repository. Instead, let Spring Boot's dependency management (via the `spring-boot-starter-data-jpa` starter or the `spring-boot-dependencies` BOM) dictate the Hibernate version.

### What changes from Hibernate 5.3 → 5.6:
- **Generally backward-compatible**, but several older bugs were fixed that may **alter existing query behaviors** [3]. Expect subtle differences in generated SQL, especially around complex joins, subselect fetching, and collection loading.
- **Naming strategy shift**: `SpringPhysicalNamingStrategy` is **deprecated** as of Hibernate 5.5 in favor of `CamelCaseToUnderscoresNamingStrategy` [4]. If your 5.3.22 entities relied on the old strategy, you must either explicitly configure the legacy strategy or verify that column/table names remain consistent.
- **ID generator mappings**: The property `spring.jpa.hibernate.use-new-id-generator-mappings` is still available in 5.6 but was removed in Hibernate 6.x. Ensure your ID generation strategy works correctly under 5.6 [2].
- **Bytecode enhancement**: If your old project used Hibernate's bytecode enhance plugin, re-configure it for the new build. For Hibernate 5.x, use the `enhance` configuration block (not `enhancement`, which is the Hibernate 6+ syntax). The `enableExtendedEnhancement` flag can interact unpredictably with newer JDK internals—test thoroughly [5].

### Action Items:
- Add `spring-boot-starter-data-jpa` to the new project and let Boot manage the version.
- Do **not** declare an explicit `hibernate-core` version unless overriding (which you shouldn't).
- Run full regression tests on all database interactions, paying special attention to generated SQL.

## 2. Java 21 on Spring Boot 2.7.14: Unsupported Territory

**Spring Boot 2.7.x officially supports Java 11–17** [1][6]. Java 21 support was officially introduced in Spring Boot 3.1. Running Java 21 on Boot 2.7.14 **works in practice** but falls outside the tested/supported baseline [1].

### Known risk areas:
- **Reflection and module access**: Java 21's stronger encapsulation (continued from Java 17+) may cause `InaccessibleObjectException` errors with Hibernate's reflection-based property access, cglib proxies, or Spring AOP [5].
- **Third-party library compatibility**: Any library in your dependency tree must also support Java 21. Hibernate 5.6.x was tested against Java 17; while it generally works on 21, edge cases exist with bytecode enhancement and proxy generation [5].
- **No backported fixes**: Issues discovered with Java 21 on Boot 2.7 won't be fixed by the Spring team—the 2.x line is end-of-life.

### Action Items:
- Test early and thoroughly on Java 21.
- Add `--add-opens` / `--add-exports` JVM arguments if you encounter module access errors.
- Monitor for `IllegalAccessError`, `InaccessibleObjectException`, or `NoClassDefFoundError` at startup.

## 3. Accumulated Breaking Changes: Spring Boot 2.3 → 2.7

The jump from 2.3.2 to 2.7.14 spans **four major releases**. Here are the breaking changes most likely to affect your project:

### 3.1 Spring Boot 2.4 Changes [3]
| Area | Change | Impact |
|---|---|---|
| **Config processing** | Property file processing rules fundamentally changed | Complex multi-document YAML profiles may need `spring.config.use-legacy-processing=true` |
| **Config locations** | `spring.config.location` no longer fails silently | Prefix optional files with `optional:` |
| **Embedded databases** | H2/HSQL/Derby: file-based DBs no longer "embedded"; default `sa` username removed | Set `spring.datasource.username=sa` explicitly for H2 |
| **JUnit 4** | Removed from `spring-boot-starter-test` | Add `junit-vintage-engine` or migrate all tests to JUnit 5 |
| **Logback** | `logging.file.max-size` → `logging.logback.rollingpolicy.max-file-size` | Update property names |
| **Web properties** | `spring.mvc.locale` → `spring.web.locale`; `spring.resources.*` → `spring.web.resources.*` | Update property names |

### 3.2 Spring Boot 2.5 Changes [7]
| Area | Change | Impact |
|---|---|---|
| **SQL init ordering** | `data.sql` runs **before** Hibernate DDL by default | Set `spring.jpa.defer-datasource-initialization=true` if you need schema generated first |
| **Init properties** | `spring.datasource.*` init props → `spring.sql.init.*` | Update property prefixes |
| **JPA** | `getById` replaces `getOne` in Spring Data JPA | Naming collisions may cause `LazyLoadingException` |
| **Startup order** | Beans using `DataSource` may need `@DependsOnDatabaseInitialization` | Annotation may be required for correct initialization order |

### 3.3 Spring Boot 2.6 Changes [4]
| Area | Change | Impact |
|---|---|---|
| **Circular dependencies** | **Prohibited by default** | Refactor circular bean references or set `spring.main.allow-circular-references=true` |
| **Path matching** | Default changed from `AntPathMatcher` to `PathPatternParser` | Security matchers like `mvcMatchers("hello")` must become `mvcMatchers("/hello")` |
| **Naming strategy** | `SpringPhysicalNamingStrategy` deprecated | Switch to `CamelCaseToUnderscoresNamingStrategy` or explicitly configure legacy |
| **Springfox** | Incompatible with `PathPatternParser` | Will cause fatal startup errors; migrate to Springdoc |
| **Removed code** | All 2.4 deprecations removed | Audit for deprecated API usage |

### 3.4 Spring Boot 2.7 Changes [6]
| Area | Change | Impact |
|---|---|---|
| **Auto-configuration** | `spring.factories` deprecated; use `.imports` file | New custom auto-configurations should use the new mechanism |
| **Security** | `WebSecurityConfigurerAdapter` deprecated | Migrate to `SecurityFilterChain` bean pattern |
| **MySQL driver** | Coordinates changed: `mysql:mysql-connector-java` → `com.mysql:mysql-connector-j` | Update dependency declarations (affects 2.7.8+) |
| **MSSQL driver** | Encryption enabled by default in v10 | May break existing database connections |
| **H2** | Upgraded to 2.1.120 (backward incompatible) | Test all H2 usage thoroughly; SQL syntax may differ |
| **Flyway** | Database-specific modules extracted (e.g., `flyway-mysql`) | Must add separate modules if using Flyway |
| **Test properties** | `@SpringBootTest` properties now override CLI args | May affect test configuration |

## 4. Introducing Hibernate into the New Repository

Since the target repository does **not** currently use Hibernate, you're adding it fresh. Key steps:

### 4.1 Dependency Setup
```xml
<!-- Add to pom.xml -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>
```
Let Spring Boot 2.7.14's BOM manage the Hibernate version (5.6.15.Final). **Do not** declare an explicit Hibernate version.

### 4.2 Configuration Properties
Migrate your `application.properties`/`application.yml` JPA settings, watching for:
- Renamed properties (use the `spring-boot-properties-migrator` dependency temporarily to catch these automatically [1][2])
- `spring.jpa.hibernate.ddl-auto` behavior may differ subtly between 5.3 and 5.6
- `spring.jpa.hibernate.naming.physical-strategy` — explicitly set if you need to preserve the old naming behavior

### 4.3 Entity Migration
- All entities using `javax.persistence.*` remain valid (the `jakarta.*` namespace change only applies in Spring Boot 3.x / Hibernate 6.x) [2].
- Verify that any custom `@Type` annotations, `UserType` implementations, or `AttributeConverter` classes compile and function correctly against Hibernate 5.6.
- Audit entity mappings for features that may have changed behavior between 5.3 and 5.6 (e.g., `@OrderBy`, `@Any`, cache concurrency strategies).

## 5. High-Risk Areas & Recommended Testing Strategy

### Critical Test Areas:
1. **Schema generation** — Compare DDL output between 5.3.22 and 5.6.15 for any column type or constraint differences.
2. **Query behavior** — Run integration tests for all JPQL, Criteria API, and native SQL queries.
3. **Lazy loading** — Bytecode enhancement and proxy generation behave differently on Java 21.
4. **Transaction boundaries** — Verify `@Transactional` propagation, especially with self-invocation and nested calls.
5. **Circular dependencies** — If the old project had any, they'll fail on 2.6+.
6. **H2 in tests** — If using H2 for testing, the 2.1.120 upgrade is backward-incompatible.
7. **Connection pools** — HikariCP is the default; verify pool sizing and timeout settings for your environment.

### Recommended Migration Order:
1. Add `spring-boot-properties-migrator` to catch property renames.
2. Introduce `spring-boot-starter-data-jpa` and let Boot manage versions.
3. Migrate entity classes and JPA configuration.
4. Address circular dependencies and naming strategy changes.
5. Run full test suite, fix failures.
6. Remove the properties migrator dependency before going to production.

## Uncertainty & Gaps

- **Hibernate 5.3 → 5.6 specific API deprecations**: The official Hibernate migration guide at `docs.jboss.org` returned a 404. Specific internal API changes (Session methods, SPI changes) between 5.3 and 5.6 were not fully documented in the sources found. Testing is the primary mitigation.
- **Java 21 + Hibernate 5.6 edge cases**: No authoritative source documents all Java 21 incompatibilities with Hibernate 5.6. The combination works in practice but lacks official certification. Organizations running this stack in production should allocate extra QA time.
- **Spring Boot 2.7 EOL**: Spring Boot 2.7 reached end-of-life on November 24, 2023. This means no further bug fixes or security patches. The migration should ideally plan for a subsequent upgrade to Spring Boot 3.x.
